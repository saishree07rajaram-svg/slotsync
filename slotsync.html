📋 SlotSync (PS-08) — Business Rules Matrix

Rule ID Rule Name Enforcement Description
R1 Exact 1-Hour Slots Server Slots are exactly 1 hour long and aligned to the hour (e.g. 14:00 - 15:00).
R2 7-Day Booking Window Server Only the next 7 days (including today) are bookable. Beyond 7 days returns 400 OUT_OF_RANGE.
R3 Single Active Booking Server + DB A slot can have only one active booking per resource. Duplicate attempt returns 409 SLOT_TAKEN.
R4 No Past Slots Server No bookings for slots that have already started or passed. Returns 400 PAST_SLOT.
R5 Fair-Use Limit (KEY CHALLENGE) Server Max 2 active booked hours per registration number, per resource, per day. Exceeding returns 422 LIMIT_EXCEEDED.
R6 Mandatory Fields Server + UI Name, Registration Number, and Purpose are strictly required and cannot be empty strings.
R7 Cancellation Frees Quota Server A cancelled booking frees the slot and no longer counts toward the 2-hour daily limit.
R8 No Auth Required System Users identify via college registration number for fast lab access without login hurdles.

🔌 REST API Specification Contract

GET /api/resources

Returns list of all bookable lab resources with status and capabilities.

GET /api/slots?resource={id}&date={YYYY-MM-DD}

Returns hourly availability for the resource and date with state (available/booked/past).

POST /api/bookings

Creates a booking. Strictly enforces R1-R6. Returns 201 on success, 409 or 422 on conflict.

GET /api/bookings?reg={regNo}

Returns active and historical bookings for the registration number ("My bookings").

DELETE /api/bookings/:id

Cancels booking, frees the slot, and restores the student's fair-use quota.
